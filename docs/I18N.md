# Italiano + inglese: regole per le pagine del sito pubblico

Il sito pubblico è in italiano (senza prefisso) e in inglese (prefisso `/en`). Le pagine restano **statiche**: la lingua sta nell'indirizzo.
**Mai** leggere cookie, header o `searchParams` per scegliere la lingua nelle pagine pubbliche (le renderebbe dinamiche e costerebbe a Vercel).
L'area cliente non ha `/en`: segue il cookie `gb_lang` (già dinamica).

## Pezzi pronti (non cambiarli senza motivo)
- `lib/i18n/index.ts`: `Lang`, `L(lang, it, en)`, `localHref`, `switchPath`, `EN_STATIC_PATHS` (elenco pagine che hanno la versione inglese).
- `lib/i18n/seo.ts`: `alternatesFor(path, lang)` (canonical + hreflang), `pageUrl`, `OG_LOCALE`.
- `lib/i18n/content-en.ts`: traduzioni di nomi servizi, giorni, orari fissi nel codice.
- `components/i18n/LocLink.tsx`: al posto di `next/link`; in inglese aggiunge `/en` agli indirizzi interni.
- `components/i18n/LangProvider.tsx` + `useLang()`: la lingua nei componenti client (il provider è già nei layout).
- `components/layout/PublicShell.tsx`: cornice comune; `app/(public)/layout.tsx` (it) e `app/en/layout.tsx` (en).

## Come si converte una pagina `app/(public)/X/page.tsx`
1. `git mv "app/(public)/X/page.tsx" "app/(public)/X/view.tsx"`.
2. In `view.tsx`: togli `metadata`, `generateMetadata`, `revalidate`, `dynamic`; esporta `export default async function XView({ lang }: { lang: Lang })` (se la pagina ha `params`/`searchParams`, passali: `XView({ lang, params, searchParams })`). Tutti i testi visibili diventano `L(lang, 'italiano', 'english')` (o `lang === 'en' ? <>…</> : <>…</>` per blocchi di JSX). Gli import dei CSS restano nel `view.tsx`.
3. Nuovo `app/(public)/X/page.tsx` (italiano): `metadata` con `alternates: alternatesFor('/X', 'it')`, gli stessi `revalidate`/`dynamic` di prima, e `export default function Page() { return <XView lang="it" />; }`. Titolo e descrizione italiani **identici a prima**.
4. Nuovo `app/en/X/page.tsx`: `metadata` in inglese con `alternates: alternatesFor('/X', 'en')` e `openGraph: { locale: OG_LOCALE.en }`, stessi `revalidate`/`dynamic`, `export default function Page() { return <XView lang="en" />; }`.
5. Pagine con `[slug]`: stessa cosa, con `generateStaticParams` e `generateMetadata` in tutte e due le versioni.
6. Per la home: `app/en/page.tsx`.

Se `view.tsx` importa un componente "client" con testi, aggiungi la prop `lang` (se è un server component) oppure usa `useLang()` (se è client). Link interni: `LocLink` (o `localHref(lang, '/x')` quando serve una stringa).

## Regole di traduzione
- La versione **italiana non deve cambiare** (stesso testo, stesso HTML, stesso aspetto).
- Inglese naturale e semplice, tono caldo e professionale (barberia di quartiere, a Foggia). Niente testi inventati, niente prezzi o orari nuovi, niente promesse non presenti nell'italiano.
- Nomi propri e marchi restano uguali (Barberia Garofalo, nomi del team, nomi dei prodotti). Prezzi in `€`. Date con `en-GB`, numeri e orari 24 ore come nell'originale.
- Servizi: usa `serviceName(lang, name)`; per testi nuovi aggiungi le traduzioni in `lib/i18n/content-en.ts`.
- Contenuti scritti dall'admin nel database (descrizioni, articoli, offerte): se manca la traduzione si mostra l'italiano (non lasciare mai vuoto). Non creare migrazioni.
- Testi legali (privacy, termini): traduzione fedele con l'avviso «Courtesy translation. The Italian version prevails.»
- Nessun riferimento nuovo a chi ha costruito il sito. Palette nero/oro invariata.
- Accessibilità: tradurre anche `alt`, `aria-label`, `title`, `placeholder`, messaggi di errore e toast.
- Niente `innerHTML`/`eval`. Niente dati finti.

## Controlli
- `npx tsc --noEmit` deve passare per i tuoi file.
- `npm test` deve restare verde. Un test controlla che ogni pagina in `EN_STATIC_PATHS` abbia la cartella in `app/en` e viceversa.
